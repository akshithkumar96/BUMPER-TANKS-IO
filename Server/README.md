# Bumper Tanks Game Service

Run locally with `dotnet run --project Server/BumperTanks.Server.csproj`.

Endpoints: `GET /health`, `GET /v1/profiles/{playerId}`, `POST /v1/rewards/daily`, `POST /v1/matches/complete`, and `GET /v1/leaderboard`.

Profile and reward data are persisted locally in JSON for development. Telemetry is retained across restarts and capped at the newest 10,000 events. Request validation accepts the 32-character hexadecimal player and match IDs generated by the Unity client, restricts telemetry to the game event names, and bounds submitted match totals. These checks protect data shape and storage size; they do not authenticate a player or prove a match result. Production deployment must use authenticated persistent storage and verify outcomes from the multiplayer authority before awarding currency.

Profile data is persisted locally in `data/profiles.json`; override this with `Storage__ProfilePath` for a mounted volume.

## Container deployment

Build with `docker build -t bumper-tanks-service Server`. Run with `docker run -p 8080:8080 -e Cors__AllowedOrigins=https://your-game.example bumper-tanks-service`.
