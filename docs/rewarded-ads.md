# Rewarded video setup

The project ships with an empty `Assets/Resources/LevelPlaySettings.asset`. Rewarded video remains disabled until the Android/iOS app key and rewarded ad unit ID are filled in. You can recreate it with **Assets → Create → Bumper Tanks → LevelPlay Settings**. Consent defaults are conservative (`gdprConsent` false and `ccpaDoNotSell` true); review the game's consent flow and jurisdiction requirements before changing them. The settings are applied before `LevelPlay.Init`.

Install package `com.unity.services.levelplay` 9.6.0 (already listed in `Packages/manifest.json`), then configure Android/iOS apps, mediated networks, and rewarded ad units in the LevelPlay dashboard. WebGL does not initialize the SDK; its ordinary server daily spin remains available.

Set the server secret as `Rewards__LevelPlayPrivateKey` in the deployment secret store. For Docker Compose, supply it as `BUMPER_LEVELPLAY_PRIVATE_KEY`. Never put it in Unity assets or the client. Configure the LevelPlay rewarded S2S callback to call:

`https://<your-api-host>/v1/rewards/ad/levelplay-callback`

Include the provider's user ID, reward units, event ID, timestamp, and signature fields, plus the `challengeId` custom parameter supplied by the SDK using `LevelPlay_Rewarded_Server_Params`. LevelPlay timestamps use UTC `YYYYMMDDHHMM` format. The signed string is exactly `timestamp + eventId + userId + rewards + privateKey` (MD5 hex). Daily spins and post-match double-reward offers each use an authenticated, one-time challenge. Match challenges are bound to the persisted player, match, and exact base award. The app requests the appropriate challenge before showing an ad. A daily-spin challenge is unique per player and day, and a match challenge is unique per player and match. This binds the callback's unsigned custom challenge ID to the intended reward and prevents shifting a valid signed event to another pending challenge. Only the S2S callback completes it; client-side ad callbacks merely poll for the server result. Challenges and event-to-challenge bindings persist with profile data, and repeats of the same callback are acknowledged only for the original binding without another grant. Callback timestamps are checked against the challenge window and LevelPlay's retry age.

For production, configure `Rewards__RequireMatchAttestation=true` and a 32-byte-or-longer `Rewards__MatchAttestationSecret` for trusted externally submitted match results. With Docker Compose, provide `BUMPER_REQUIRE_MATCH_ATTESTATION=true` and `BUMPER_MATCH_ATTESTATION_SECRET`. Keep the API reachable over HTTPS and validate LevelPlay custom-parameter macro names against the account's S2S callback settings. App keys, ad unit IDs, the private signing key, attestation secret, and dashboard callback configuration are external deployment setup and are intentionally not committed.
